# Cyrene Memory

> 为 AstrBot 打造的 **个人向、工程化、情感化** 长期记忆补全插件。群聊交给 LivingMemory，私聊交给它。

---

## 🌟 核心理念

市面上的 AI 记忆系统往往走向两个极端：
- **纯文件流（如 OpenClaw）**：完全依赖 LLM 的“自觉性”去读写文件。容易漏记、断片，面对长任务时频繁失忆。
- **纯图谱流（如初代 Cyrene Agent）**：状态门控复杂，各种写入路径各自为政，且容易把真正活跃的记忆错误衰减。

**Cyrene Memory** 采用**工程化多维架构**，结合了本地 SQL 的确定性、向量检索的模糊性，以及状态机的连续性。我们不只是在做“备忘录”，我们在为赛博伴侣构建“认知脑区”。

---

## 🏗️ 六大记忆分区（认知架构）

为了彻底解决“记忆职责错位（如把排查流水账塞进用户画像）”的痛点，本插件严格划分了六大模块：

| 模块 | 认知科学对应 | 定位 | 存储与更新方式 | 注入策略 |
| :--- | :--- | :--- | :--- | :--- |
| **L0 画像 (Profile)** | 陈述性记忆 | **绝对静态**的“我是谁、基建字典”（称呼、偏好、API Key、绝对路径）。 | 长度硬限制 40 字，越界触发精简。 | 作为常驻背景注入。 |
| **L1 工作记忆 (Working)** | 工作记忆 | **当前动态**的“正在做什么”（临时路径、当前报错、任务进度）。 | 支持 `old_key` 融合纠错，防止过时信息堆积。 | 高优先级上下文注入。 |
| **L2 长期事件 (Episodic)** | 情景记忆 | 带有情绪色彩的故事（“折腾了三天的 bug 终于修好了”）。 | 由 LLM 评估重要度与情感标签。 | 结合本地向量按需召回。 |
| **原始数据 (Raw Logs)** | 短时感觉记忆 | 对话流水的**无损原文**（不做任何压缩）。 | 每 50 条自动切片打包为 `zip` 冷数据。 | 默认不注入，供反思与重总结检索。 |
| **任务看板 (Tasks)** | 执行控制 | 跨天的长线工程进度（“MCP 联调”）。 | 状态机管理 (active/paused/done)。 | **永远置顶注入**，防断片。 |
| **关系状态 (Relationship)** | 情感状态 | 当前关系阶段与近期情绪底色。 | 随高优 L2 事件自动演变覆盖。 | 作为人格基调注入。 |

## ⚡ 核心黑科技

### 1. 混合召回（关键词 + 本地向量）
不再死板依赖“关键词匹配”。系统集成了轻量级语义检索，调用本地 `qwen3-embedding:0.6b`。
即使你问“之前那个老是不理人的毛病怎么修的”，它也能跨越字面意思，精准捞出“排查 dispatch 接口 payload”的底层记忆。

### 2. 记忆自主融合与纠错 (Self-Correction)
模型具备记忆的编辑权。当它发现 L1 中存在冲突（如 `旧IP: 192.168.1.1` vs `新事实: 192.168.1.2`）时，它不会粗暴地覆盖或保留冲突。它会调用带有 `old_key` 参数的工具，**融合旧信息、写入新事实、并自动销毁过时条目**。

### 3. 切片冷数据归档 (Cold Data Archiving)
“原始数据”无限膨胀会拖垮数据库。系统每积累 50 条新对话，会自动将最老的 50 条打包成带时间戳和 ID 范围的 `.zip`（如 `l1_20231101_20231102_ID1-50.zip`）存入 `archives/` 目录，释放内存。

### 4. 带“历史透视”的重新总结 (Deep Re-summarize)
在 WebUI 点击“重总结”时，系统不仅会看当前数据库，还会**穿透检索冷数据压缩包**。大模型会结合历史归档，为你重新生成最准确的记忆值。

### 5. 后台反思与模型回退 (Reflection Engine)
当对话积累到阈值，插件会在后台静默调用轻量级模型（如 GLM-4-Flash）。将流水账提炼为 L0 事实和 L2 故事。支持主备模型切换与自动重试，保证反思永不落空。

## 📦 安装与依赖

- AstrBot `>= v4.24.2`
- Python 标准库（无需额外 pip 安装）
- **本地 Ollama**：需部署 `qwen3-embedding:0.6b` 模型（用于向量化，配置在插件面板中）

将插件目录放入 `<astrbot-data>/data/plugins/astrbot_plugin_cyrene_memory/`，重启 AstrBot 即可。首次启动会自动建库。

---

## ⚙️ 配置面板说明

在 AstrBot 后台的插件配置中：
- **LivingMemory 兼容层**：配置 LivingMemory 的 `db_path` 以及身份识别别名。
- **Memory Injection**：控制注入的记忆种类与最大字数（默认 1500 字）。
- **Embedding**：配置 Ollama 的 API 地址、模型名称。
- **Reflection**：配置触发反思的条数（如满 15 条触发）、主模型 ID 与回退模型 ID。

## 🖥️ WebUI Dashboard

在 AstrBot 后台点击插件页即可访问，提供企业级的数据管理：
- **数据看板**：实时展示 L0、L1、L2、关系、任务、原始数据六大维度的数量。
- **L0 画像**：一键“编辑”、“精简”（大模型洗稿）、“重总结”（穿透压缩包检索）、删除。
- **原始数据**：查看近期流水账及已归档的冷数据列表。
- **全中文界面，深色护眼主题，完全响应式。**

## ⚠️ 开发与避坑指南

1. **AstrBot LLM 工具参数限制**：
   `@filter.llm_tool` 对 `float` / `int` 声明极不友好，会导致静默注册失败！**所有参数请用 `str` 声明**，在函数体内转换。
2. **向量写入注意**：
   请求 Ollama 时必须加 `asyncio.Semaphore(1)` 全局锁，防止低配 CPU 崩溃。
3. **防生硬注入**：
   注入块只在前缀生效（`req.prompt = block + req.prompt`），绝不修改历史记录，完美保护 Prompt 缓存。
