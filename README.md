# Cyrene Memory · 三级人格记忆

> 给 AstrBot 用的长期记忆插件。目标不是「把对话存下来」，而是让记忆像人的记忆：
> 相关时自然浮现，久不用渐沉下去，但不会被删除。

---

## 为什么会有这个

大多数记忆插件做的是「存—取」：把对话切片、向量化、按相似度捞回来，整块塞进 prompt。

问题是机械。每次注入的都是同一批内容，用不上的信息占着预算，真正相关的反而被挤到后面。
时间久了，记忆变成一个只进不出的仓库，而不是一个会淡忘、会联想的东西。

这个插件想解决三件事：

1. **分层** —— 恒定的事实、正在发生的事、久远的故事，不该用同一种方式存
2. **浮现** —— 该出现什么，由当前话题决定，而不是每轮固定注入
3. **渐沉** —— 久不用就往下掉，但保留在库里，而不是物理删掉

---

## 数据模型

七张表，三个记忆层级加一个原料池。

### L0 · 核心画像 `l0_profile`

存**恒定事实**：身份、偏好、忌讳、环境。

只在明确出现新信息时才写。默认什么都不写 —— 写进一条假的，比漏掉十条真的糟糕。

实际内容长这样：

```
[identity]   身份背景     = 正在经历早八的大学生
[preference] 输出格式偏好 = 信息量大的内容一律渲成图片发送
[environment] dsh_web地址  = https://100.64.0.1（Caddy 自签）
```

### L1 · 工作记忆 `l1_working`

存**正在做的事**：过程性事实、临时结论、当前卡点。

条目有寿命。七天内没更新、且跌出最近 50 条的，会被切片压缩成 zip 归档，从主表移走 —— 不是删除，是降级。

### L2 · 长期事件 `l2_events`

存**带情绪的故事**：这个人身上发生过什么，他当时是什么心情。

这一层最难写好。判据是：把这句话讲给朋友听，像不像在说一个人？

```
好  跑满 41 次还去操场 —— 把任务过成了习惯
好  早八第一节全程划水，第二节才听明白，课后说要改作息
差  用户提出了重启前任务管理习惯      ← 动作转述
差  考虑调整作息                    ← 空洞，等于没写
```

被反复引用的事件，`importance` 会累积上升。

### 原料池 `raw_logs`

原始对话，七天过期。是反思器的输入，不是给人看的。

### 辅助表

- `tasks` —— 长线任务看板
- `relationship_state` —— 关系阶段与近期氛围
- `embeddings` —— 向量，按 `record_type` 区分归属层

## 注入机制

预算默认 3500 字符，按层切分：

| 层 | 配额 | 策略 |
| --- | --- | --- |
| 骨架层 | 10% | `identity` 类 L0 常驻，不参与排序 |
| 浮现层 | 38% | 其余 L0 + L1 + L2，按相关度排序后填充 |
| 剩余 | 52% | 留给对话本身 |

注入挂在 `@filter.on_llm_request` 上，拼在 `req.prompt` 前缀而不是 `system_prompt` —— 保护 system prompt 的缓存命中。

---

## 渐淡

排序分数是相关度和新鲜度的乘积：

```
score = 相关度 × (0.30 + 0.70 × 0.5 ^ (天数 / 半衰期))
```

那个 0.30 是刻意的地板。再久不用的东西也只是沉到后面，不会被剔除。

这就是「渐淡」和「过期删除」的区别 —— 人的记忆不会因为十年没想起来就消失，它只是变得很难被想起。

---

## 反思器

`raw_logs` 攒够 10 条未反思原料时，后台起一轮反思。

**prompt 的骨架**：

- 最重要的一条：默认什么都不写，绝大多数对话都该返回空数组
- 判断三问：一年后还成立吗？说的是这个人还是这件事？跟当前话题无关时它还有用吗？
- 口语检查：把写出来的句子当成朋友转述给他听，会不自然吗？
- 四条禁令：空洞概括 / 动作转述 / 一次性事件 / 你自己干的活

**上限**：L0 最多 2 条，L2 最多 3 条，都默认 0 条。

反思模型可配主备两个，失败自动重试。

---

## 语义去重

L2 写入前先查重，阈值 0.80：

1. 与库里既有条目比对
2. 与本批已接受的条目比对（它们还没入库，查不到）

命中就合并 —— 保留原条目，把新的 `importance` 叠加上去。

---

## cron 唤醒过滤

定时任务唤醒会往会话里注入一大段指令文本。如果让它进 `raw_logs`，反思器会把「请用 send_message_to_user 汇报」提炼成「用户提出了汇报习惯」这类垃圾。

两道拦截：

1. **按来源判断**（主）—— `platform_meta.name == "cron"`，或 `_extras` 里带 `cron_job`
2. **按关键词兜底**（辅）—— 正文含 `[CronJob]`、`【重要】结论必须` 等标记

来源判断是后加的，因为关键词会失效 —— 注入正文的前缀有时会被剥掉。

## 工具接口

给模型主动写入用的四件套：

| 工具 | 用途 |
| --- | --- |
| `cyrene_record_event` | 记一件有情绪的事（L2） |
| `cyrene_update_profile` | 更新恒定事实（L0），单条 40 字以内 |
| `cyrene_update_working_memory` | 更新当前工作状态（L1），支持 `old_key` 覆盖纠错 |
| `cyrene_update_task` | 建/更新长线任务看板 |

| 命令 | 说明 |

| `cyrene_recall <关键词>` | 手动检索 |

## 配置

```json
{
  "memory_injection": { "enabled": true, "max_chars": 3500 },
  "reflection": {
    "enabled": true,
    "trigger_count": 10,
    "primary_provider_id": "zhipu/glm-4.7-flash",
    "fallback_provider_id": "deepseek/deepseek-flash",
    "max_retries": 1
  },
  "embedding": {
    "enabled": true,
    "api_url": "http://127.0.0.1:11434/api/embed",
    "model_name": "qwen3-embedding:0.6b"
  }
}
```

`trigger_count` 是最需要调的旋钮。太小，原料不够，反思器会凑废话；太大，信息压太久才落库。10 是当前的经验值。

## 已知问题

诚实记录，免得后来的人重新踩一遍。

**L2 取景仍偏动作转述**（2026-11-20）

L0 已经能稳定写出「这个人是怎么想事的」，但 L2 仍会产出「在任务看板上划掉了 xxx」这种流水账。
prompt 里的口语检查和正反例都写了，模型只遵守了一部分。

样本还太少（两轮），暂时不改，先跑几天看真实分布。下次动手的两个方向：

1. 明写「l0 已写下的偏好，l2 不得复述」
2. 把「在…了」「完成了」「划掉了」这类句式列进禁令

**短句去重阈值偏严**

长文本调出来的 0.80，用在短句上按不响。实测：「考虑调整作息」和「给自己设了 22:30 闹钟」相似度只有 0.621，语义明明一样，机器认不出来。

长句去重是有效的（实测撞到过 0.925 并成功合并），短句这块还没解。

## 安装

```bash
cd /path/to/astrbot-data/data/plugins
git clone https://github.com/Lichfa0405/astrbot_plugin_cyrene_memory.git
```

依赖本地 embedding 服务（默认 Ollama + `qwen3-embedding:0.6b`）。关掉 embedding 也能跑，会退化成纯关键词召回。

重启 AstrBot 生效。
